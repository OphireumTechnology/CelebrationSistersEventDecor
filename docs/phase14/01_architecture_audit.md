## 1. Executive Baseline Summary

The repository on `main` (`91b56a86`) provides a strong Phase 13 hardened foundation: React 19 + Vite 8 + Tailwind CSS v4 frontend, Express 4 + TypeScript backend (`server/app.ts`), PostgreSQL repository adapter (`server/repositories/postgresRepository.ts`) + normalized repository (`server/repositories/normalizedRepository.ts`), SQL migrations `001`–`006`, HMAC-signed `HttpOnly` session cookies + Supabase JWT verification + TOTP MFA + CSRF protection (`server/auth.ts`, `server/authz.ts`), distributed rate limiter (`server/rateLimit.ts`), Resend email adapter (`server/notifications.ts`), transactional notification outbox (`server/outbox.ts`), and 11 automated test suites (`tests/*.test.ts`).

However, the **"Book a Private Consultation"** experience is currently implemented only as a single-screen preliminary event inquiry form (`src/components/ConsultationModal.tsx`) targeting `POST /api/bookings`. It lacks a separate consultation appointment scheduler, real-time planner availability engine, conflict-free consultation slot locking, Railway PostgreSQL compatibility for `auth.uid()` references in migrations `002`/`003`/`005`, complete consultation lifecycle email templates, an administrative consultation command center (calendar, CRM pipeline, staff availability, outbox monitor), and scoped public consultation status/reschedule/cancel tokens.

## 3. Prioritized Phase 14 Remediation Plan (Dependency Order)

1. **Migration `007` & PostgreSQL Reconciliation (Block 14.3):** Add `db/migrations/007_consultation_scheduling_and_railway_rls.sql` to reconcile Railway PostgreSQL `app_current_user_id()` / `users_self_or_admin_select` without breaking Supabase or weakening RLS, extend `consultations` with UTC slot & concurrency exclusion constraints (`btree_gist`), add `staff_availability_rules`, `consultation_slot_holds`, and `crm_follow_up_tasks`, expand `notification_outbox` categories, and enforce RLS across all new tables.
2. **Domain Types, Scheduling Engine & Resend Templates (Blocks 14.4, 14.6, 14.8):** Implement `server/scheduling.ts` (operating hours, buffers, timezones, blackout dates, slot holds, concurrency checks, appointment state machine, cryptographic public access tokens) and expand `server/notifications.ts` + `server/outbox.ts` to cover all 14 customer and internal notification events.
3. **Backend Consultation, Availability & CRM APIs (Blocks 14.5, 14.8, 14.9):** Extend `server/app.ts` and `server/repositories/normalizedRepository.ts` with all consultation scheduling, status lookup, reschedule, cancel, confirm, assign, complete, proposal handoff, staff availability, CRM pipeline, and reminder endpoints while preserving 100% of existing API contracts and security guardrails.
4. **Premium 4-Step Booking Wizard & Admin Consultation Command Center (Blocks 14.2, 14.7, 14.8):** Upgrade `src/components/ConsultationModal.tsx` into a luxury, accessible, responsive 4-step wizard with live backend slot calendar + self-service status/reschedule/cancel view; build `src/components/AdminConsultationCommandCenter.tsx` and integrate it into `src/components/PortalsWorkspace.tsx` for Admin and Staff/Planner roles.
5. **Automated Test Suite, CI Hardening & Acceptance Documentation (Blocks 14.10–14.13):** Add comprehensive Phase 14 frontend, backend, database/RLS, notification, and security tests; update CI triggers and migration checks; execute all local verification gates; document all evidence honestly.
